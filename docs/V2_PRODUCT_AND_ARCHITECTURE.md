# 饭宝 V2：产品与架构基线

## 1. 产品定位

饭宝不是外卖商城，而是两个人共同经营的一间数字小餐厅。核心闭环是：

1. 双方表达这一餐想吃什么。
2. 系统找出共同选择、冲突和可替代方案。
3. 双方确认本次菜单与做饭安排。
4. 完成后记录照片、评价和改进建议。
5. 历史记录与个人偏好成为下次推荐依据。

产品以情侣为默认场景，数据模型保留扩展到亲子、家庭或合住成员的能力。普通成员在点餐和确认上平权；空间所有者只额外拥有成员与危险设置管理权限。

## 2. 个性化原则

个性化是核心能力，不是附属设置页。系统必须同时满足：

- 首次使用立即可用：内置主题、菜单栏目和示例菜品模板。
- 情侣共同拥有：空间名称、背景和菜单是共享内容，修改后双方同步可见。
- 成员保持个性：每个人可配置称呼、头像、头像框和个人强调色。
- 跨端一致：同一份配置能在微信小程序和 H5 安全渲染。
- 可演进：以后增加主题时，不需要迁移每个页面的散落样式。

### 2.1 共享外观

每个情侣空间拥有一份受控外观配置：

- 空间名称与欢迎语。
- 主题预设。
- 页面背景类型与背景图。
- 主色、伴侣色、强调色、背景色、文字色。
- 卡片样式和圆角等级。
- 四个主导航的自定义名称。

前端只能渲染白名单中的设计令牌，不执行用户提交的 CSS、HTML 或脚本。

### 2.2 成员外观

成员资料与账号身份分离，支持：

- 在当前空间中的显示名称和关系称呼。
- 独立头像，不强制等同于微信头像。
- 头像框和个人强调色。
- 口味偏好、过敏和忌口。

### 2.3 菜单个性化

菜单不是固定页面数据，必须由服务端持久化：

- 菜单名称、封面和展示风格。
- 栏目名称、图标或图片、排序和布局风格。
- 菜品名称、图片、描述、标签、排序和可用状态。
- 默认菜单通过模板复制到新空间，复制后完全归该空间独立编辑。

## 3. 核心信息架构

### 今天

- 当前早餐、午餐或晚餐。
- 我想吃、对方想吃、共同想吃。
- 推荐及推荐理由。
- 确认菜单、开始制作、完成记录。

### 菜单

- 菜单与栏目切换。
- 搜索和偏好筛选。
- 快速表达想吃。
- 菜品、栏目和菜单外观管理。

### 记录

- 已完成餐食的时间线。
- 照片、参与成员、做饭者、评价和备注。
- 菜谱尝试与下次改进。

### 我们

- 情侣空间和邀请绑定。
- 双方资料、偏好和忌口。
- 主题、背景、导航名称及菜单样式工作室。
- 账号、安全和通知设置。

H5 在宽屏下扩展为多列卡片与更宽的内容区；手机 H5 与微信小程序保持底部导航。

## 4. 领域模型

```text
Account
  ├── AuthToken
  └── Membership ── Space ── SpaceAppearance ── ThemePreset
          ├── Preference
          └── Invite

Space
  ├── Menu ── MenuSection ── Dish
  └── MealSession
        ├── MealChoice
        ├── MealPlanItem
        └── MealRecord ── MealRecordItem
```

重要约束：

- 所有业务对象必须属于一个空间。
- 服务端从认证令牌确定当前账号，禁止客户端提交 openid 冒充身份。
- 所有查询都先验证当前账号在空间中的有效成员关系。
- 同一成员对同一餐次和菜品只有一个有效选择。
- 餐次状态只能按 `draft/confirmed/cooking/completed/cancelled` 合法流转。
- 完成餐次和生成记录必须在一个数据库事务中执行，支持幂等重试。

## 5. API 约定

- API 前缀统一为 `/api/v2/`。
- 微信 code 只在服务端换取 openid；登录成功后返回可撤销访问令牌。
- H5 默认支持邮箱密码登录，未来可增加微信网页 OAuth。
- 成功响应接受全部 `2xx` 状态；删除可返回 `204`。
- 错误统一使用 `detail` 或字段级 `errors`。
- API 字段统一使用 `snake_case`，前端若需要 camelCase，只能在集中映射层转换。
- 图片 URL 由请求上下文或对象存储生成，不得硬编码开发机 IP。

## 6. 默认内容

内置四套系统主题：

1. 暖心餐桌：暖米白、珊瑚橙、鼠尾草绿。
2. 莓果约会：克制莓红与奶油粉。
3. 鼠尾草厨房：平静、清新的自然绿。
4. 夜色小馆：深色背景、杏橙与低饱和蓝灰。

新空间初始化一份“我们的默认菜单”，默认栏目为暖心主食、一起吃菜和甜蜜收尾，共八道示例菜。默认内容是可删除、可重命名、可换图和可重新排序的普通数据，不在页面代码里写死。

## 7. 交付门槛

- 全新克隆可以依照 README 安装并启动。
- Django 迁移可从空数据库完整执行且无漂移。
- H5 与微信小程序都能构建。
- 自动化测试覆盖认证、跨空间越权、个性化保存和主点餐状态流转。
- 两名测试用户可以完成：注册/登录、创建并加入空间、换主题、编辑菜单、双方选择、确认、完成和查看记录。
- 仓库不包含真实密钥、固定局域网地址或生产环境模拟成功逻辑。
